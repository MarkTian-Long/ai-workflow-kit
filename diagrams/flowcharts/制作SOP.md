# 流程图制作 SOP

用途：用一张读者能跟着走的图说明步骤、责任或状态。输入为已有说明、已确认规则和待确认项；输出为同一含义的文字说明、可编辑图源和可查看预览。本 SOP 不规定所有报告都采用同一图形或固定章节。

## 选能回答问题的图

| 当前问题 | 优先用什么 | 关键表达 |
| --- | --- | --- |
| 事情按什么顺序完成，条件不同怎么走？ | 主流程图 | 节点写动作，箭头写顺序，判断出口写条件，返工指回具体步骤 |
| 谁负责做和确认，工作怎样跨角色流动？ | 角色协作图/泳道图 | 泳道写实际责任角色，节点仍写动作，跨泳道箭头写交接；不能用部门框代替责任 |
| 同一个对象会变成什么状态，异常能否恢复？ | 状态迁移图 | 节点写状态，箭头写触发事件或条件；交代重试、取消、超限及终止，避免把状态和操作混为一谈 |

## 制作与核对

1. **先定读者要做的判断。** 一张图回答一个主要问题，明确起止边界和完成条件。读当前权威输入；冲突、未知和未授权动作要保留，不能为了让图顺畅而补成事实。
2. **还原必要关系。** 列出完成目标不可缺少的动作或状态，以及它们的顺序、依赖、责任和条件。只有会改变路径或判断的内容才入图；图形种类从这些关系推导，不从现有模板倒推业务。
3. **写清节点和连线。** 动作采用“动词＋对象”，状态用稳定名称；同一对象前后一致。保持箭头含义一致。每个判断出口说明条件；检查是否互斥、是否覆盖必要情况，未知就标待确认。并行、等待和交接要明确，不能让一条普通箭头暗示系统已有并发或接口能力。
4. **让主路径可顺读。** 优先自上而下或从左到右，保持字号和留白，减少交叉线。条件贴近对应连线，不压住节点或泳道标题；长句放旁注。图太密时按实际读者问题拆图并保留衔接，不能只靠缩小文字塞进画布。
5. **逐条走通。** 选一条成功路径和一条已知失败/例外路径，核对起点、条件、责任、回退位置和结果。检查文字、图源、可见预览的节点、边和条件是否一致，以及预览是否可读、有没有遮挡或溢出；不能把文件能打开当成语义正确。

## 输入改变时一起维护

先定位本次输入变化影响的文字、节点、关系、责任或条件；在同一次修改中更新说明、`.mmd` 与 `.svg`。优先维护可编辑图源，再用已有渲染器生成 SVG，或在没有渲染器时同步编辑原生 SVG；不能长期平行维护两个互不核对的版本。小包不强制安装 Mermaid 客户端。

检查本次变化和相关失败路径即可：核对新增/删除节点、连线方向、分支条件、责任归属及状态终点，再在实际使用尺寸看预览。普通桌面材料默认验桌面；有明确移动端需求或已发现窄屏问题时才追加窄屏。交付时指出使用的输入、实际验证及仍未知部分。其他呈现引用了这张图时，同步替换或明确标记旧版，保留必要恢复入口。

这三个合成例子仅演示不同关系的表达。真实项目可只取一种、合并或采用更合适的图；先核对业务条件，不把示例中的角色、两次判断或重试路径变成通用规定。
