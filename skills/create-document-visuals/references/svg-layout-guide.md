# 显式 SVG 布局：用于交接与复杂关系

当现有自动布局不能满足读者需要，或需要明确角色位置、自由分组、边界和标注时读取。SVG 是可编辑源；HTML 可作为最终阅读容器。共享交付要求见 [执行参考](workflow-reference.md)。

## 从问题推导版式

先用 [流程与交接参考](flowchart-guide.md)核对必要语义，再选择空间安排：

- **谁负责、如何交接**：用角色分区，每个动作只归属一个责任方，沿时间顺序连接。跨区线表达交接，分区相邻不自动代表存在关系。
- **模块边界、调用或数据流**：先定组件和边界，再定关系方向与图例；调用、数据和包含关系使用不同文字/线型，不能只靠颜色。
- **概览与局部**：概览保留阶段衔接，局部回答一个具体问题。不要按原文段落机械生成一张张流程图。

不为填满模板新增角色、判断或节点；需要合并、增加分区时按实际输入修改。

## 使用一个可编辑起点

[role-handoff.svg](../assets/layouts/role-handoff.svg)是自建的合成“资料复核与补充”示例，包含提交方、受理系统、复核人三个角色和一条返回补充路径。它不是业务事实，也不是固定审批模式。

1. 在父文档的 source 目录建立当前图源，替换示例文字、对象和关系。
2. 根据实际动作和标签调整节点、分区及画布，保持 SVG 的固有 `width/height` 与 `viewBox`。
3. 先布分区与节点，再算连线端口。连线先绘制，节点后绘制；不要用节点覆盖线条来掩盖错误连接。
4. 主路径易于顺读；分支就近，回路走外侧。折线转折点和边标签避开其他节点、分区标题及线段。
5. 节点文字可以换行，字号保持正常阅读可读；需要容纳更多信息时扩大节点、拆图或调整布局，不靠缩字硬塞。

样式参数见 [diagram-style.json](../assets/diagram-style.json)：沿用蓝灰步骤、黄色判断、浅绿结果、灰色补充/异常语义和本地 Microsoft YaHei 字体。颜色不代表真实能力验证结果；角色、条件与结果仍以文字表达。用户已认可的参考与配色优先。

该 JSON 是显式布局的参数参考，不会被现有 Mermaid-lite renderer 自动读取；修改它不会自动重绘已有 SVG。若另有布局脚本参与生成，连同脚本登记唯一再生成关系，避免两份可编辑真值。

## 可选几何标记契约

需要自动几何检查时沿用以下标记。标记提供可测量对象，不证明图中角色或规则真实。

| 对象 | 标记方式 | 测量约定 |
| --- | --- | --- |
| 节点组 | `<g data-visual-node="stable-id">` | 同组放主形状与节点文字，ID 在图内唯一 |
| 主要形状 | `data-visual-shape="true"` | 节点组内恰好一个主要 rect/polygon/path；比较文字与这个形状，而非整个组 bbox |
| 连线组 | `<g data-visual-edge="edge-id" data-from="node-id" data-to="node-id">` | 起止 ID 必须对应已有节点；连线 path 标 `data-visual-line="true"`，同组可放条件文字 |
| 分区组 | `<g data-visual-region="region-id">` | 分区边框标 `data-visual-shape="true"`，分区标题与边框留安全距 |

不要在节点组中混入其他节点，或把分区边框标为节点。组合形状/旋转文字/曲线路径等超出检查器能力时，应记录无法判断并人工检查，不能默认为通过。对菱形文字还需检查斜边实际内域，只有矩形 bbox 包含并不足够。

## 最低充分验收

- XML 可解析，viewBox 与尺寸非零；所有字体、图片和引用在本地可用，无脚本或外部资源。
- 核对语义与角色归属，所有边指向正确对象；分区、边、节点 ID 与源关系一致。
- 使用原有 renderer 的 `image` 命令导出 PNG，检查中文、箭头与裁切；同时在最终 HTML/Markdown 容器等待字体加载后检查实际文字边界和阅读顺序。
- 目视核对连线端口、穿越、交叉、条件标签及实际字号。自动几何结果无法替代这些语义和版式判断。
- 按实际阅读场景覆盖桌面；明确移动需求、已有窄屏验收约定或实际问题才增加窄屏。
- 保留替代文本、图注和必要文字兜底；没有完成必要检查时记录限制。

引用 PNG 或 SVG 生成成功不等于图已验收；候选模板可用性不等于正式业务采用。
