# 流程与交接图：按问题选表达

仅在制作含分支、回路、状态变化或跨角色交接的精确图时读取。共享的源文件、离线处理、嵌入和记录要求见 [执行参考](workflow-reference.md)。

## 先确定读者要判断什么

| 读者问题 | 表达方式 | 必要语义 | 当前能力边界 |
| --- | --- | --- | --- |
| 接下来做什么，条件不同会怎样？ | 流程图 | 起止、动作、分支条件、每条分支去向、回路 | 现有 Mermaid-lite 可表达方框、菱形、箭头和一级分区 |
| 这一步谁做，交给谁，何时接手？ | 角色交接图 | 责任角色、动作归属、交接输入/结果、异常返回对象 | 使用显式 SVG；Mermaid-lite 分区不等同自动泳道布局 |
| 对象在什么事件后改变状态？ | 状态图 | 状态、转换事件、条件、回退和终止含义 | 原生状态图用[标准 Mermaid 分支](mermaid-standard.md)；现有 parser 只能以流程语法作状态示意 |
| 多个参与方按什么时间顺序发消息？ | 时序图 | 参与方、消息顺序、同步/异步与失败路径 | 现有 parser 不支持 sequenceDiagram，改读[标准 Mermaid 分支](mermaid-standard.md) |
| 模块之间存在什么关系？ | 层级/依赖图 | 模块边界、关系方向、边的含义 | 不把依赖箭头误读成业务执行顺序；需要时改读 [SVG 布局参考](svg-layout-guide.md) |

简单线性文字足够回答问题时，沿父任务约定保留列表；用户明确需要画图时照其目的制作。不按固定节点数决定是否需要图。

## 把输入变成可核对的关系

先从当前输入整理这四项，再写图源：

1. **对象与责任**：每个动作或状态指向谁；谁决定，谁只是接收结果。
2. **主路径**：触发后依次发生什么，在哪里结束；“配置/发布”与实际业务执行是否属于不同问题。
3. **分支与返回**：判断条件是否互斥、覆盖哪些情况；重试回到哪一步，取消或终止如何处理。
4. **事实边界**：哪些关系输入已经确认，哪些缺失。缺失关系先保留为待确认项，不为了闭合画面新增审批、网关、角色或结果。

把动作写在节点，把条件写在边上。同一判断有多种结果时逐项核对；不把“否”统一画成结束。未知条件会改变业务含义时，先解决该缺口再完成精确图；可以独立制作已确认的概览。

## 在现有 Mermaid-lite 中落源

语法细节见本文件的 [Mermaid-lite 语法](#mermaid-lite-语法)；原生时序、状态与 ER 图按[标准 Mermaid 分支](mermaid-standard.md)选独立引擎，不交给现有 parser。类图等未开放图型需另行验证引擎，或用显式 SVG 保留其关系：

- 只用 `flowchart LR/RL/TD/TB`、带引号的方框/菱形、`-->`、`-- "条件" -->` 和一级 `subgraph`。
- 先按入口到结束的业务顺序声明节点，再写边。跨分区边放在各分区 `end` 之后，避免把另一分区节点重复归属进当前分区。
- 首次声明的顺序影响布局排名。回路是已确认的业务返回关系，不用回边偷偷调整主链。
- 保留有业务意义的完整文字；长标签可用 `\n` 主动换行。换行不能删去判断条件、责任或例外。
- 不支持的管道边标签、其他 Mermaid 图种、样式指令、嵌套分区等应失败，不能静默丢弃后继续交付。

先 `inspect` 核对结构，再 `diagram` 生成 SVG/PNG。计数一致只证明结构数量一致。

## Mermaid-lite 语法

现有 parser 只接受以下子集，不等同完整 Mermaid：

- 方向头：`flowchart LR`、`flowchart RL`、`flowchart TD`、`flowchart TB`。
- 节点 ID：英文字母或下划线开头，随后可有数字、下划线和连字符；节点文字用双引号。
- 形状：方框 `A["步骤"]`、菱形 `B{"条件？"}`；标签内用 `\n` 换行。
- 无标签箭头：`A --> B`；有标签箭头：`A -- "是" --> B`；可写链式边。
- 一级分区：`subgraph stage_id [阶段标题]`，以单独的 `end` 结束；节点只归属一个分区。
- 空行和整行 `%%` 注释。

~~~mermaid
flowchart TB
A["接收资料"]
B{"资料完整？"}
D["处理并归档"]
C["补充资料"]
A --> B
B -- "是" --> D
B -- "否" --> C
C --> A
~~~

拒绝：管道标签 `A -->|是| B`、嵌套/重复分区、分区内 direction、单独裸节点引用、未闭合分区、尾随未知语法，以及 `style/classDef/click`、`sequenceDiagram/classDiagram/mindmap/C4` 等非此子集语句。不能只改文件扩展名来使用新图型，也不能近似改写后省掉原语义。

## 布局选择与调整

浅层主链先试 LR；阶段较多或存在长回路时先试 TD/TB。检查实际输出的起点到终点扫描顺序，再决定方向。主路径应易于顺读，分支就近汇合，回路走外侧。

自动布局出现交叉、箭头穿节点、文字拥挤或明显无效留白时，先调整声明顺序、方向或拆分概览/局部图。仍不能满足已确认版式时，改用显式 SVG；使用 [角色交接模板](../assets/layouts/role-handoff.svg)前读取 [SVG 布局参考](svg-layout-guide.md)。图的业务关系保持不变，唯一编辑源随实际路线登记。

## 验收时回答三个问题

- **关系正确吗？** 逐项对照动作、条件、角色、交接、回路、终止和人工决定；没有为了美观新增依赖或省略异常。
- **读得出来吗？** 在最终阅读容器和实际桌面图宽检查字体、分区顺序、边标签、交叉与遮挡。手机需求、既有约定或已发现窄屏问题才增加窄屏检查。
- **后续改得动吗？** 唯一源、同版本导出、图注与文字兜底能够相互定位；PNG 不是精确图的唯一源。

仅结构检查通过时标为 `structural-only`；没有完成语义和实际显示检查就不写为视觉通过。几何检查也不能证明业务正确。
