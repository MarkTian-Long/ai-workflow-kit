# 流程与交互分析

在既有分析步骤2—4中按需使用。适用于业务改进、产品功能分析、跨角色交接、系统或人机协作；当活动、资料流转、上下游依赖或反馈关系可能改变问题判断时读取。保持用户已确定的目标、产品与权限边界。

## 从目标进入现状

先确认服务谁、要改善什么结果、分析对象及起止边界，再选一个有代表性的实际案例还原过程。制度描述、参与者回忆、实际记录可能不一致，要分别标来源；缺少记录不能直接证明某一步不存在。

把三种内容分开：证据支持的现状、待核实的关系假设、拟议的优化方案。没有现成流程的新工作可以构造候选交互，用假设和验证条件表述，不称为现行流程。绘图中使用的判断条件、角色权限、先后顺序和数据可得性也需要证据。

## 按关系选择表达

当全局关系会影响判断时，在局部分析前先展示一张最小充分的概览图。用一句话交代业务目标和起止边界，在图中以文字并配合高亮或边框标出“当前讨论节点／范围”，显示关键上游输入、下游接收者或依赖；不只靠颜色定位。全局取足以改变当前判断的用户任务或业务范围，不默认扩到整个组织，也不以通用研发阶段代替实际业务流程。

流程是活动与交互的关系模型，不预设成线性步骤。按当前问题保留有意义的：

- **顺序与交接**：上一步什么结果使下一步可以开始，由谁交给谁；等待、责任转移及交付物版本是否明确。
- **条件分支**：条件是什么，由谁或什么规则判断；不同结果去哪里，未知或材料不足怎样处理。
- **并行与汇合**：哪些活动确实可以独立进行，哪些互相依赖；汇合是全部完成、任一完成还是其他条件。图上分叉本身不证明并行。
- **反馈与循环**：什么触发修改、复审或下一轮迭代，具体返回哪个活动；何时继续、结束、转人工或终止。当前任务返工与下一批任务的持续改进分开。
- **跨角色或系统的往返**：请求与回应、人工与工具动作、异步反馈以及状态变化；不能将实际多轮交互压缩成单向箭头。

按关系选择流程图或相关可视化：业务路径用流程图，跨角色交接用泳道，消息往返用时序图，状态与转换用状态图；非流程问题可用能力关系图或因果图，不虚构串行步骤。节点用易懂的业务动作或结果命名，关键箭头标明交付内容或触发条件，图上用文字或线型区分现状、待核实关系和拟议变化。短表可补节点细节，不能替代适用场景中的概览图。

只展开会影响当前判断的关系。大图先给概览，再展开关键支路；不靠删分支或缩小文字获得整齐。已有当前有效且覆盖本题的图时，复用并标出本次范围，避免重复绘制。向读者交付可直接阅读的图：聊天可用可渲染的 Mermaid，其他表面使用当前可用的绘图能力；若无法渲染，明确限制并改用静态图或可直接打开的可视化，不把绘图源码当作已经展示的图。核对当前节点、标签、关键连接方向和返回路径是否清楚；具体渲染规范由所用能力承担。

## 同时检查活动与连接

对关键活动记录以下信息，可合并进已有表格，不要求每次填写全部字段：

| 检查对象 | 需要弄清的关系 |
| --- | --- |
| 输入 | 现在实际有什么，完成这一步需要什么；来源、提供者、有效版本、质量、到达时机与允许使用范围。将已有、可取得、缺失及不适用分开。 |
| 动作与判断 | 谁负责，做什么转换或判断，依据什么规则，哪些例外或决定仍需人工。 |
| 输出 | 实际产出什么，下一方需要什么，谁接收，什么条件下可接受或需要返工。 |
| 连接 | 怎样触发下一步，依赖是否满足，分支如何汇合，等待或异常退回哪里；循环的继续和退出条件。 |
| 证据与缺口 | 真实案例、日志或资料在哪里；哪些关系仍是推测，找谁核实。 |

输入输出不限于文件或数据，也可能是事件、状态、资源、权限、业务解释和人工决定。检查交接两侧是否匹配：上游“已输出”不等于下游“可使用”；需要时关注字段含义、版本、时点或状态的不一致，而不默认展开接口和数据库详细设计。

## 从问题证据推导优化

在现状和缺口上定位重复劳动、等待、返工、信息丢失、规则冲突或责任不清，再核对原因。信息不足时先安排补证或最小案例回放，不能直接把猜测作为建设需求。

根据目标比较删除无效步骤、简化、改变顺序、调整交接与责任、补齐输入、并行处理或自动化等改法。AI只是可能手段之一。评估整段任务的结果、质量、总投入及维护成本，避免只证明一个节点更快却将负担移到下游。改图时同步检查受影响的分支、汇合、循环和人工决定。

用真实或明确标注的测试案例验证改法，覆盖会改变结论的正常路径、关键分支和返工路径；阈值、责任和输入不足时保持待确认。流程图帮助发现和检验问题，不能单独证明因果关系、业务采用或收益。

## 交付与停止

适用时以“简短结论 → 标出当前节点的全局概览图 → 局部证据与方案”组织交付，保留关键输入输出与缺口、问题证据、候选改法和最小验证；已有文档能承载时原位补充，不另建平行事实源。得到足够依据支持当前决定后停止展开；无需画出整个组织或所有系统。

适用性反例：已有订单或服务处理的等待与返工可以用此方法；尚未明确用户和价值的战略选题，应先比较目标、需求与证据，再判断是否需要流程模型；已确认流程的纯绘图或单点文字修改，直接执行，不重新跑业务发现。
