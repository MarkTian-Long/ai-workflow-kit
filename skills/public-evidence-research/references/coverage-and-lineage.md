# 覆盖与谱系核查

仅在大范围、多轮或已出现漏项的公开研究中使用；普通问答不必建完整台账。

## 先建立可解释的发现框架

按**上层业务任务**建主分类；行业、终端行业、模态、实时性、独立检测/材料内联动/跨材料关系、应用/平台/底层、采购阶段和时间窗口作交叉轴。可重叠，不将八类维度硬拆为互斥销售模块。

检索至少从不同发现路径挑选会改变覆盖判断的方向：
- 业务任务及近义词：审核、质检、复核、监测、合规、预警、服务评价、流程管理、存档；
- 采购语言：招标、征集、单一来源、限价、候选、成交、中标、合同、验收、续签、维保、升级、扩容、替换；
- 权利/资源：本地化、私有化、软件许可、永久、年度、座席、用户、实例、并发、分钟、存储；
- 供应商/买方：品牌与法定名称、原厂与集成商、第一及其他候选人、上游系统、采购方集团/分支；
- 行业/业务端：分别记采购人的行业与最终被服务的行业；例如运营商为金融客户采购服务不应自动排除。

**不要**因为已有三家供应商或找到成交案例就标“行业已覆盖”。同样不要求枚举所有供应商×行业×年份笛卡尔组合。用检索日志说明哪些组合有实际搜索，哪些缺证、访问失败或因低相关停止。

## 建议的四层对象与一个角色表

| 层 | 建议主键和最小字段 | 计数注意 |
| --- | --- | --- |
| 来源 Source | S-ID、发布主体/标题/日期、原URL、访问日、官方/自述/转载/摘要、原文定位、实际取得状态 | 一项目有多个来源；“在线可读”与“已下载”分开 |
| 采购事件 Event | E-ID、项目ID、项目编号/包号、轮次、征集/招标/候选/结果/合同/验收、金额原单位/税费、来源ID | 同轮重招/候选/结果分开，不重复计独立项目 |
| 采购项目 Project | P-ID、采购方、任务、层级、输入模态、流程、部署、许可与规模、成本责任、重要未知 | 一个项目覆盖多个任务/模态只计一次 |
| 系统谱系 Lineage | L-ID及所关联P-ID、首建/扩容/续签/升级/替换、日期、关系证据、未证实部分 | 同名不同项目不强并；同一系统多个项目仍有不同采购事件 |
| 供应商/角色 | 法定主体、品牌/产品、原厂/集成商/运维/BPO/候选角色、来源ID | 公司集团、子公司和产品品牌不自动等价 |

供应商页、产品页和行业协会应用介绍分别统计，不混入采购项目数。若无法证明独立系统总数，报告“未知”而不是用项目数代替。

## 一轮研究结束前的遗漏审计

1. 用真实任务中的核心业务词和最强可比案例回查；看采购名称是否换了“客户经营”“展业”“投诉运营”“风险控制”等词。
2. 从代表性中标供应商及其他候选人出发，找同任务近年案例及旧系统的维保/升级；同品牌不同法定主体单独核对。
3. 从采购方/终端行业出发查官方采购门户、结果目录、代理及公开技术附件；没有外部招采也查机构应用披露/厂商案例，但降低证据等级。
4. 抽取几条看似重名或金额接近的记录，核对编号、包号、轮次、发布日期、服务范围、金额阶段，避免重复或者错误关联。
5. 对“新案例图/供应商清单”逐项给出处置：漏收并补入；已在总库但被价格子集排除；属于已有项目新阶段；无关/重复；或待核。

## 判断“可以停止本轮搜索”

以覆盖证据和新增边际价值共同判断，而不是固定数量或工作轮次。记录：
- 已使用的任务词/同义词、主要供应商与买方反查路径、主要平台、时间组和来源类别；
- 最后一批新增是否仍改变分类、授权/费用结构、交付/验收责任和重要未知；
- 未覆盖领域、可访问障碍、未核原件、内部验证责任及重新开启的证据触发条件。

“本轮定向检索已达可交接状态”不同于“全网穷尽”。如果用户明确要求尽可能完整，不能因写出包装建议就提前关停项目发现。
