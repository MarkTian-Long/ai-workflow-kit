# 会话沉淀与续接

把一次收口请求落实为可靠保存和可继续推进的交接。默认当前会话；归档和新建分别依据用户明确要求。基于 v0.2 的可移植版本；实际使用取决于宿主的安装、发现和调用。

## 先读权威要求

读取包内冻结的 [沉淀与复用标准](references/learning-reuse.md) 的当次保存、范围/续接和八行回执；本 Skill 只组织执行。落点遵守接收工作区现行的正式入口和适用 SOP，项目事实留在所属项目。宿主要求优先；冲突时明确差异，不自动覆盖本地规则或扩大授权。已读且未变可复用。

原生会话能力是条件依赖：实际创建、读回、归档必须使用宿主已提供且获授权的工具。工具或权限不足时，完成仍可安全执行的保存，明确缺少的能力和剩余动作；保留旧会话，不用 Prompt、文件或模拟结果冒充新建/归档，也不为补能力擅自安装连接器、改数据库或扩大权限。

## 识别这一次要做什么

从用户原话提取范围、是否归档、是否新开。六种请求均执行下节的完整沉淀并读回核验，区别仅为范围和沉淀后的会话动作；不适用项按实际处置，不强制新增资产。自然语言不限固定命令：

| 请求 | 范围和结果 |
| --- | --- |
| 沉淀 | 当前会话完整沉淀并核验，保持会话 |
| 这个会话沉淀并归档 | 当前会话完整沉淀并核验 → 归档当前会话 |
| 这个会话沉淀归档，开新会话继续 | 当前会话完整沉淀并核验 → 新会话建成并读回 → 归档旧会话 |
| 本轮全部沉淀 | 总控及确认成员完整沉淀并核验，保持这些会话 |
| 本轮全部沉淀并归档 | 总控及确认成员完整沉淀并核验 → 归档这些会话 |
| 本轮全部沉淀归档，开新总控继续 | 总控及确认成员完整沉淀并核验 → 新总控建成并读回 → 归档旧成员 |

指定部分会话按实际范围处理。范围确实不清才集中问一次；已有授权不逐步重问。用户只要求制定/修改本机制时，不把讨论文字当实际归档或创建请求。

## 执行当次保存

1. 从任务原目标、可见历史、正式当前状态和输出找本次增量。优先读当前文件；需要聊天证据时用原生 read_thread 的有界分页补查，不把摘要当全部历史，不全盘扫描聊天。
2. 按统一标准分别处置成果/调研、已完成与待办、重要纠正、实际复用信号。重要分析仅在聊天时主动整理到所属正式位置；现成成果核对并补入口，避免重做。待办保留具体动作、责任、阻塞、触发和依据。
3. 对高价值且可跨任务复用的新增方法、结论、证据或纠正，按任务类型、复用范围与权属定位已有共用资产，核对主版本正文，依统一标准完成授权内的回流处置。场景细则从所属工作区或主题入口按需读取；项目事实留在原项目。已有规则漏执行先纠正执行。
4. 实际读回受影响正文及直接入口，核对已完成事项、待办和范围。把用户点名、主动发现、回放分别记录；测试/一次保存不证明长期收益。不修改原生 memories；真实授权边界仍适用。
5. 若仅保存，交付结果与统一八行回执后停止。若涉及多个会话、归档或新开，按需读取 [多会话与原生交接](references/group-handoff.md)，执行用户授权的剩余动作；归档前按该参考复核最新要求及保存/续接证据的有效性。

## 汇报

按既有面向用户完成汇报要求，先说明实际完成范围、保存位置、共用资产处置和待办/失败。随后按统一字段说明给出八行回执：内容、正式去向和实际处置写入既有字段，区分已回流、已有内容承接、候选、待授权及未完成；整组可一份汇总，成员覆盖留既有记录。归档未请求时按标准写 NOT_READY，这不表示保存未完成。续接/归档未完成不能提前宣称全部完成。

长期复用成效、重复错误趋势和机制调整交给后续任务与既有手动审计；本次只为它们留下可靠输入。
