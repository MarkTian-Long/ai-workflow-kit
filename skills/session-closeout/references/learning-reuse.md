# 沉淀与后续复用标准

状态：`frozen snapshot`；本文件是随本发布快照冻结的通用依赖，基于 2026-10-15 的统一标准适配。它不替换接收环境的正式规则，也不是运行标准的第二个维护主源。

本文件统一沉淀、发现、使用、效果判断与复核的共性要求。工作区只补材料落点和局部约束，项目保留事实与实际证据；不建立跨项目业务正文副本。现有用户授权优先，规则不自动扩大权限。

## 触发与读取

- 实质任务在首次交付前，按任务对象与拟交付物定位直接相关的已有方法、候选或资产，读取当前主版本并核对适用边界；入口链接存在不等于已读或已经执行。纯问答、简单格式修改和无相关经验的任务不制造记录。
- 明确要求沉淀、维护候选/复用机制，或出现可复用纠正、重复失误、实际复用成败、来源/工具变化时读取本规范。同一任务已读且未变可复用；不是每轮全读候选台账、聊天或历史证据。
- 工作区入口负责给出可按主题命中的索引；方法或候选必须有使用触发、实际消费者及读取入口。没有入口时优先修入口，不复制成另一套规则，也不为获得触发而启用 Skill。
- 无历史或局部历史的子 Agent，由派发者传入直接适用的经验主位置和边界，并由子 Agent 核对；主协调合并实际使用及错误，不把同一任务的多个子轨计作独立复用。

## 处理闭环

`核对已有经验 → 按边界使用 → 记录实际帮助或失败 → 保留、修订、合并或退出`

出现新增经验时，先保存可执行结论和证据，再在后续合格任务中验证。当前任务完成、记录保存完成和长期效果成立分别判断；效果待观察不要求持续占用当前会话，也不阻止已经满足验收条件的本轮交付。

- 项目事实、状态、决策和等待：写回所属正式控制面；验证准确、当前及可续接，不为每条事实计算方法收益。
- 可复用方法、模板、流程：说明下次遇到什么问题、采取什么动作、何时不适用，先复用已有候选；实际效果按下节观察。
- 画像及稳定偏好：保留原话、范围和替代解释，按画像治理确认；模型执行错误与新增需求不能自动归为用户偏好。
- 权限、安全与明确约束：按其权威来源持续遵守，不因低频、未出事故或缺少效率收益而停用。
- 一次性细节、重复内容、未经证实推断：留在原任务必要证据中或明确无需另行沉淀，不机械新建规则、Skill、模板或候选。

## 最小信息与唯一位置

一条经验应能通过原记录及引用回答以下问题，无需在每份文件复制完整表格：

1. **结论与动作**：解决什么问题，下次具体做什么。
2. **使用条件与入口**：何种任务适用、何时读取、何时不适用，以及权限/资料边界。
3. **来源与主位置**：可追溯来源、当前有效内容的唯一位置；候选索引不手抄资产的当前版本。
4. **状态与授权**：候选、受控验证、已采用或退出；生命周期与效果证据分开，验证次数不构成晋升授权。
5. **后续观察与证据**：适用机会、发现方式、实际使用阶段、帮助、失败及额外负担；证据留在实际任务或既有方法记录。
6. **复核与处置**：下一次具体使用机会或约定复核日、维护责任、改变或退出条件及本次处置。

来源 Work/Artifact/Task、登记时间、验证时间和敏感级别按需合并展示，保留可追溯性。索引只留当前判断和来源链接；资产台账维护当前路径/版本/生命周期，原任务记录实际事件。已有 Skill 的累计效果仍写其既有记录，不另建跨工作区累计台账。

## 当次沉淀的保存与回流

沉淀负责当前会话承担的任务或明确指定的一组任务的可靠收口，为后续任务和既有手动审计提供输入。长期效果评估、跨任务治理和后台调度仍由既有机制承担；纯讨论不制造文件。任务内原有主动发现与安全回流要求继续适用，明确沉淀时检查遗漏，无需用户逐条指定保存内容。

- **已完成成果与调研**：核对正式成果、关键结论、可靠来源及版本、重要失败路径、验证结果和适用边界。已完成但仅留在聊天中的高价值分析，按所属主题整理到已有正式位置；已有成果只补实际缺失内容和发现入口，不重跑已经验证的工作、不复制整段聊天或每次操作。历史缺失或不可见时说明缺口，不能把压缩摘要当作全部历史。
- **待办与续接**：把未完成的具体动作、责任、阻塞、触发条件及必要依据写入所属当前状态；同时保留已完成事项及成果入口，避免新会话重新投入。业务待办与方法后续验证分别归位，等待事项不写成已完成；会话归档不等于业务验收或 Work 关闭。
- **纠正与复用信号**：保存改变本轮结论或下一次行动的重要纠正、否决原因，以及已有方法的实际使用、失败或负担。已有规则未执行先纠正执行，不叠加同义规则；单次反馈不自动晋升画像或全局原则。
- **向共用资产回流**：按适用范围、权属和敏感性匹配项目方法、工作区共用资产或用户级方法的现有主版本。对高价值且可跨任务复用的新增方法、结论、证据或纠正，形成明确处置：已更新主版本及位置、已核对由现有内容承接、保留候选及下次触发、待授权、未完成/阻塞，或不适用及原因。当前授权覆盖的安全可逆维护直接完成；未获授权的正式晋升、Skill/画像/权限等变更准备具体差异后交决策，不因沉淀自动扩权。客户事实留项目，不逐层复制业务正文。
- **保存证据与来源**：实际读回受影响正文、必要入口和状态，核对活动主版本及引用；记录主动发现、用户点名或事后回放，保存完成、实际使用和后续收益分别判断。只新增证据、失败或判断变化时更新原记录；无变化重复沉淀不刷新流水、不重复建候选。

用户看到的成果汇报应说明保存了什么、在哪里、待办与复用处置、仍缺什么；适用的八行回执在下节统一维护。记录可合并到已有 CURRENT、EVENTS、正式成果或方法维护记录，不为每个检查项建文件。

## 会话范围与安全续接

- 默认范围是当前会话承担的任务内容，包含可见历史中的相关决定，并非只处理最后一条消息。指定部分会话时只覆盖这些成员；“本轮全部”指已有派发/关联记录确认的总控与成员，不按相近标题、时间或同项目猜测。沿用已有当前记录保存成员、职责、成果入口和收口进度，不另建全局会话台账；范围不清才集中澄清一次。
- 保存、归档和新建会话是分别判断的动作。单独“沉淀”只保存；明确要求整体沉淀归档并新开总控时，按该范围一次完成必要动作，无需用户挨个会话重复提醒。总控优先读取已有交付及正式文件，不因回执同步延迟催办重做；跨会话消息仍须具备用户授权。
- 新会话或新总控的顺序固定为：完成沉淀并读回 → 用现有原生工具实际创建 → 记录实际会话标识并核验项目归属 → 新会话实际读取正式交接材料、报告正确的已完成/待办/边界/下一动作 → 归档指定旧会话并核验结果。queued、仅生成 Prompt、创建成功但未读回交接均不能算续接完成。
- 在已有收口记录中，将新会话的读回证据关联到本次成员范围与正式交接内容版本，可用已有修订标识、提交号或足以识别的内容摘要，不强制逐文件计算摘要。成果、待办、关键决定、权限边界或成员范围发生实质变化时，受影响的读回结论失效；更新交接并复用已建新会话补核对。归档前复核当前有效要求及这些证据，用户暂停或撤回归档时保持旧入口。
- 新建时按业务主范围选已登记项目；用户级或跨项目工作可用无项目会话。新会话带最小结论和正式入口，按当前材料复核，不默认继承全部聊天、外部授权或新的后台任务。它先清楚呈现现状，再在已有授权内续推；只读交接按请求停止。
- 创建失败、范围冲突、成员运行中且尚未完成安全交接、最终内容不可见或成果缺失时，保留旧入口并标明待处理成员及原因；不能据此声称整组完成或擅自终止成员。已有正式完成证据不因接口空值而被否定。外部等待已可靠交接可保持待办，不强求业务全部结束才归档。
- 每次真实创建后立即把新会话标识及进度写回已有收口记录。未知创建结果先查现有会话再决定重试；重复执行复用已建会话，只处理尚未完成的写入/归档。部分归档失败保留实际状态与补救，不重复生成资产或新总控。

## 轻量维护与临时产物

小范围文档增补、模板回流、局部整理和已定界修正，采用与实际影响相称的维护方式；安全、权限、正式来源和强制验收要求仍适用，不设机械文件数量或减量目标。

- 默认复用当前主版本、已有工具及同任务已核对且未变化的上下文。原位修改，联动仅由业务事实、活动路径、生命周期、入口或责任变化触发；来源、变更、验证和回退信息合并到既有适用记录一次收尾，不在多个README、台账和副本重复维护正文。
- 新增脚本、服务、合成示例、专用断言或多层暂存前，说明现有路径不能满足的交付要求、具体风险或强制门；不能仅为简单文档维护搭建临时工具链。排版确有变化时做受影响预览，其余使用限定检查；目标已达到且无新风险时立即交付。
- 临时副本、镜像、可重建缓存和一次性工具不默认作为长期成果。收尾核对归属、消费者与复用价值，确认无后续依赖后回收到系统回收站或按授权清理；必要原始证据、来源及可恢复原字节在各自归属保留一份。打包或合并留证须核对内容、字节与入口，不能借精简删除唯一原件或掩盖未完成事项。
- 正式资产、项目事实和用户级规则分别归位，记录只作必要回链；纯讨论不制造文件。下一次真实同类任务检查新增文件、读取、联动和验证是否确有必要，以及是否减少重复劳动；保存完成不证明长期效果。

## 后续有效性怎么判断

对有实际使用机会的方法，分开观察：

- **找到**：该任务是否适用；是自动命中、用户提醒后找到、应命中但遗漏，还是证据不足。未出现机会与发现失败分开。
- **用对**：是否读取当前版本、遵守边界并在首次交付前实际使用。事后回放、同任务修正、合成检查和独立后续使用分开；同一机会不重复计数。
- **有帮助**：记录新增发现、减少遗漏/重复劳动或改变判断的具体证据，再区分真实交付/决策是否改善。对应既有 L1 执行、L2 方法增益、L3 结果；未知就写未知。
- **值得维护**：保留重复纠正、漏检、误用、阅读/维护负担、额外确认和等待等反向信号。新增需求、正常取舍不算重复错误；工具/模型或任务难度同时变化时，不把全部改善归因于沉淀。

在原任务已有 EVENTS、验证记录或方法的累计记录中，只在产生新证据、失败或判断变化时留一条：`机会/任务与经验主位置；自动找到或提醒；交付前使用或回放；具体帮助与结果/未知；负担/失败；处置与下次触发`。字段可组合进现有列，不为观察新建空表或每轮流水。

文件存在、链接通过、脚本通过、调用次数与无用户反对不能证明持续有效。缺少合格机会总数不计算总体有效率；没有可比基线不声明节省时间/token或因果提升。已通过受控检查只证明该范围可用。

## 复核与退出

- 复用、失败、用户纠正、版本/工具/权限变化立即触发相关复核；既有明确验证窗口和复核日继续有效，不因本次标准更新重置。
- 后续相关任务的执行者维护原任务证据；方法维护者汇总唯一当前结论。既有手动审计只核对新增、变化、到期、高风险或反复摩擦对象，使用相同标准；本规范不新建或恢复后台调度。
- 有机会却未找到：修发现入口；找到却未执行：纠正执行；正确执行仍无增益或负担过高：收窄、合并、修订或提出退出。不要每次在底层追加一条同义规则。
- 无机会：记录缺少哪类真实消费者，按原窗口给出处置，可保留按需参考；不制造任务凑样本，不把低频等同无价值。已有权限/安全要求不适用按收益退出。
- 到期须形成实际结论：证据不足、保留受控验证、收窄、待补来源、合并或退出，并写具体原因及下一触发；不只刷新日期，不把记录复核时间改写成业务验证时间。
- 当原结论已被当前规则或资产承接，候选只保留来源和正式主位置。被合并/替代内容保留索引与恢复证据，未经授权不物理删除。
- 已授权、可逆的维护直接完成；正式画像、Skill、权限、自动化、业务主版本或验收边界变化遵循既有授权。进入真正决策门前完成差异、来源、影响、验证和回滚准备，不重复请求已有授权。

## 沉淀审计与归档

用户单独发送“沉淀”或要求本任务沉淀/回写结论时，执行仅沉淀审计；仅讨论机制或概念不触发。明确要求归档、关闭会话、结束后转新任务时，才进入归档前审计。已经明确授权的归档不重复确认，但须满足适用审计条件。

沉淀仅授权范围内的查重、结论/状态/证据回写、候选维护和验证，不授权归档会话、删除文件、关闭业务 Work 或扩大权限。`CURRENT` 可按实际已授权工作的完成情况记录 `done`；这不代表业务验收或会话归档。单独“沉淀”不能作为关闭 Work 的依据。

先给成果汇报，再保留以下独立八行回执；字段名不得省略、改名或以普通总结/表格替代。回执格式只在本规范维护，各入口引用本节。八行是标题加七个字段：

```text
[沉淀审计]
archive_readiness: READY_TO_ARCHIVE / NOT_READY
已回写：
新建或更新的候选：
画像观察：无 / 候选摘要（未晋升） / 已获确认并晋升
无需沉淀：
仍需用户决定：
验证结果：
```

- 仅沉淀固定写 `NOT_READY（未请求归档，当前会话保持）`；它描述归档条件，不表示本轮工作未完成。
- `READY_TO_ARCHIVE` 只用于当前仍获授权的归档且适用保存/续接检查通过；仅表示具备条件，不表示工具已归档，也不表示全部外部等待或后续事项结束。用户已暂停归档时写 `NOT_READY（用户已暂停归档，旧会话保持）`。
- `已回写` 写清具体成果或可复用增量 → 正式主位置 → 实际改动；回流到共用资产要说明回流了什么。仅核对既有内容时写“已核对，由某主位置的既有内容承接”，不得称为已更新。待办与已完成事项的保存可合并说明。
- `新建或更新的候选` 仅列尚未正式采用的候选及状态，证据与下次触发可指向原记录；正式资产已更新的内容归入 `已回写`，被正式承接的旧候选只保留来源回链。
- `无需沉淀` 只放不适用、已核对的重复或一次性细节及原因。候选待验证、待授权、未执行和阻塞不得藏在这里；分别在候选、用户决定或验证结果中如实说明，未获授权的正式变更先准备具体差异。
- `验证结果` 分清本轮保存/检查、续接/实际归档结果和后续效果/未知。归档写已归档、部分失败或未执行及原因，以实际工具结果核验；用户暂停时明确“未执行归档，旧会话保持”。可引用已有证据，不添加第九行字段或宣称未来收益已成立。
- 没有变化可写“已审计，无新增沉淀”；不因此重复建文件、更新无变化时间戳或重跑全量校验。
- 总控整组沉淀可交付一份覆盖明确成员的汇总八行回执，在既有字段和来源记录中说明成员覆盖、保存位置及例外；已核对的成员不必重复发送同义沉淀消息或回执。缺失最终交付或必要证据的成员不能被汇总掩盖，也不得误标整组 READY。
- 发送前逐项核对八行与实际记录；首次或再次遗漏均先检查规则读取和模型执行，不以简洁或目录为由省略。

工作区适配：遵守接收工作区现行的正式控制面和适用审计要求；画像或长期偏好的修改另按接收环境的治理和用户授权执行。
