# 多会话与原生交接

仅在多会话、归档或新开模式读取。共同安全顺序以包内冻结的 [沉淀与复用标准](learning-reuse.md) 为准；接收环境的有效要求及当前用户授权优先。

## 固定范围与进度

**默认成员**：用户说“系列会话／本轮全部”且未另列名单时，只取当前总控及本会话界面“已创建的任务”。用户明确纳入的既有会话再补入；同项目、相似标题、业务关联、来源引用不证明成员关系。子 Agent 的成果归所属主会话，不另算用户可见成员。

**快速定位**：先用当前界面已知名单、创建回执或既有 CURRENT 的成员 ID，直接定向读取；缺少 ID 时才用 list_threads 补定位，找到即停，不先按关键词扫描相关会话或全项目。工具不能直接读取“已创建的任务”时，复用已知截图／记录，不推测列表外成员。创建成功时就在既有 CURRENT/交接记录补成员标识、职责及成果入口，避免下次重新发现；不另建成员索引。

**成员自行沉淀**：总控按已知 ID 向确认成员各派发一次沉淀任务，由每个会话基于自身上下文、用户纠正和正式成果检查并落盘；总控同时沉淀自身承担的内容。派发写清范围、直接适用标准、成果位置、写入所有权及停止条件，保留用户选择的模型和设置。成员只写所属成果或独占的沉淀记录，共享 CURRENT/台账及共用资产由总控单写；成员通过最终回复和成果入口交付，总控读取，无须互发确认消息。跨会话消息须具备用户授权；权限或工具不可用时标明该成员待处理，不以总控代读冒充成员执行。

**最小核对与汇总**：已有成员自行沉淀的结果覆盖当前范围且内容未变时直接复用；普通研究交付、文件已保存或总控汇总不等同于成员已沉淀。总控用 wait_threads 按已知 ID 批量等待进展，必要时有界 read_thread 补缺口，核对成员是否保存了结论与依据、聊天中的重要增量、待办和纠正/复用处置，再整合冲突和共享入口。已验证且未变的研究、构建和验收不重跑，不因读取延迟重复催办。成员自身上下文也可能压缩，具体缺口由该成员按需补读或说明；不能声称已覆盖不可见的全部历史。

在已有 CURRENT/交接记录保留实际成员、正式成果、待办及保存／新建／续接／归档进度。回合结束不等于业务完成，读取延迟不能催办重做。缺少成员自行沉淀证据、运行中且未安全交接、未知成果或冲突成员保持待处理，不自行终止；未齐全时不得宣称整组完成。必要消息须已有用户授权。

## 新建与读回

使用当前可用原生工具，名称随运行时以实际 schema 为准，禁止直接改聊天数据库、伪造会话或用复制 Prompt 冒充创建。Codex app 常用链：list_projects / create_thread / wait_threads / read_thread / set_thread_archived / list_archived_threads。

1. 核对项目登记与业务范围，跨项目或用户级交接可用 projectless。保留用户所选模型；不因交接自行选新模型、云环境或 worktree。
2. 先保存最小正式交接：已完成及验证、待办/阻塞/责任/触发、关键决定/排除/权限边界、活动材料入口和下一动作。可复用增量注明实际回流的主位置及处置，候选或待授权保持原状态，避免续接重复提炼或误当已采用。记录此次用户要求及其范围；不复制完整聊天或敏感配置。
3. 将业务交接正文与原收口者维护的创建/归档进度分开。原生创建会启动新会话，可能早于工具返回后回写实际标识；Prompt 须说明新会话不把暂时滞后的创建进度当作业务事实、创建失败或再次开会话的依据，只读核对时无需重复沉淀回执。随后在已有收口记录登记拟创建的用途和发起时间，再实际调用 create_thread。Prompt 要求新会话先读权威材料并列出正确的上述现状，再按本次授权推进；若本次是只读交接或验收则列出后停止。明确旧会话名单及本轮是否允许归档，但由负责收口者单写归档进度。
4. 立即记录真实返回的 threadId/hostId 或 clientThreadId。queued 不是已建成；clientThreadId 不能交给需要 threadId 的工具。等待实际可用标识，核验归属。创建结果未知时先定向查现有会话，不能盲目再建。
5. 用 wait_threads/read_thread 核对新会话确实读取正式材料，准确说明已完成/待办/决定和下一动作；工具创建成功或新会话仅承诺“将读取”均不够。把核对依据、实际回复来源及通过结论关联到本次成员范围和交接内容版本；结论、待办、决定、边界或成员有实质变化时，受影响的通过结论改为待核对，更新材料后复用已有新会话补读。缺项时保持旧会话可用并补本次交接，不新增 ACK/HOLD 握手或恢复暂停门。

## 归档与重试

仅归档模式：完成保存及适用审计后归档指定成员。

归档并新开模式：新会话已实际建成、归属正确且交接已读回后，才调用 set_thread_archived 归档旧成员；新会话自身不在旧名单。每次调用归档工具前，检查最新用户要求以及保存/读回证据是否仍覆盖当前范围和交接内容；暂停、撤回或证据失效时先保留旧入口。归档完成用工具返回和有界 archived 列表核验，分别报告具备条件与实际执行结果；此顺序属于执行要求，不宣称原生工具提供语义归档锁。创建或读回失败时保持旧会话；部分归档失败记录实际进度，不谎报整组完成。

重跑先读取已有收口记录，复用真实新会话标识，只补尚未完成的保存/读回/归档。档案状态不代表业务 Work 关闭；存在可靠交接的外部等待仍可留待办。最终如实返回已完成、未完成成员及可执行补救。
