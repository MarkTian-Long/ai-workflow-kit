# 交付与发布验收

## 按需求交付

默认文字；用户明确要求才做网页、日历或下载件。在既有可编辑来源上迭代。数据源统一使用 revision；更新酒店或返程时间后，时间轴、地图、交通和预算同步更新。各模块分别记数据与呈现状态，避免地图筛选覆盖路线选择。

保留一张总览地图。交通卡片说明起终点和真实入口、交通方式、出发与到达目标、估算依据、行李动作、延误处理和导航。酒店未定时标区域锚点。无道路数据就不绘仿真道路；坐标注明来源和坐标系，不混用 WGS84/GCJ02 等。嵌入受限时用支持的链接/接口，不绕过平台限制。

## 天气刷新契约

保留 provider、位置、timezone、覆盖日期、units、fetched_at、issued_at（若有）。校验日期和必要字段后才整体提交更新。null 不转成 0 或晴天；缺风或降水指标不输出低风险。获取时间不等于模式发布时间，模型预报不冒充官方发布。

有超时和重复请求保护。失败保留旧数据和旧获取时间，显示错误及官方核对入口；过去或超范围日期显示不支持/历史，不继续声称最新预测。成功时同步摘要、卡片、单位、提醒；不修改用户选择的路线。网页刷新不表示后台持续监测或景区运营已核实。

## 实际验收

| 层 | 证据 | 不能替代什么 |
| --- | --- | --- |
| 内容 | 约束、寄存、时间轴和预算人工复核 | 不证明事实真实或当前仍有效 |
| 数据 | 合成正反例、算术、引用与状态检查 | 不证明 Agent 行为 |
| 浏览器 | 桌面和手机真实点击切换、导航、预算；天气成功/失败/缺值/过期；键盘和无网状态 | 不等于在线 API 真实可用 |
| 发布 | 源文件 → 构建产物包含正确目标 → 部署完成 → 匿名目标页面标识正确 → 关键交互 | HTTP 200、仓库存在、任务绿灯各自都不足 |
| Skill | 格式/相对引用 → 宿主发现与触发 → 新会话应用 → 对照行为测试 | 发布不能替代安装或有效使用 |

每项写 passed、failed、not_run 或 not_applicable，并附实际证据。网页测试至少覆盖两个路线与日期筛选组合；地图和交通需相符。未执行的层不得借用另一层的通过结果。

## 公开与维护

公开方法只带虚构示例。真实订单、证件、联系方式、精确行踪、私密页面链接、账号和私人画像不随包发布；公开 PR 也不是私密审阅区。先获准公开范围，核对来源和许可，保留公开白名单并检查实际产物。

修订回唯一编辑源，处理远端授权修改后导出；不以旧快照覆盖新内容。发布时核对目标分支、使用条件写入、完整读回，并保留恢复提交。匿名访问受环境限制时明说未验证，不宣布所有人都能打开。
