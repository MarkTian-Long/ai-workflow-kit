# 阅读型 HTML 汇报模板

为需要读者理解结论、比较方案并决定行动的桌面报告提供一个轻量起点。适用于内部评审、研究简报、方案说明和复盘；章节数量、名称和顺序均可调整。

这是为 `ai-workflow-kit` 独立原创的通用版本。它只采用“阅读导航、结论、对比、流程、长表和证据”等高层需求，没有复制公司内部模板的 HTML、CSS、图标或业务文本，也不携带客户资料。合成示例中的人物角色、场景和用例均为演示设定。

## 文件与打开方式

| 文件 | 用途 |
| --- | --- |
| `report.html` | 带明确占位提示的空白报告骨架 |
| `example.html` | “共享工具预约流程”合成示例 |
| `styles.css` | 两个页面共用的视觉样式 |
| `report.js` | 根据章节生成目录并标记当前阅读位置 |

将四个文件保留在同一目录，双击 `report.html` 或 `example.html` 即可打开。也可以通过任意本地静态服务器预览。不需要 Node.js、Python、构建工具、账号或网络连接。

## 如何改成自己的报告

1. 复制整个目录到目标任务，编辑 `report.html` 的标题、读者、日期、结论和内容。
2. 删除不需要的章节；新增章节时沿用 `<section data-section id="稳定锚点">` 和章内 `h2`。目录自动读取 `h2`；需要更短的目录名称时设置 `data-nav-label`。
3. 保留唯一且稳定的 `id`，便于分享 `report.html#evidence` 一类本地锚点。变更章节文字不会改变已有锚点。
4. 区分已知事实、判断、假设和待确认事项。来源放在证据区，通过本地锚点引用；模板不提供事实或结论。
5. 宽表格放在 `.table-scroll` 中，保留表题、表头与可见的横向滚动提示。不要为塞下表格缩小整页字体。
6. 交付前检查实际桌面浏览器中的目录跳转、长表滚动、文字断行与链接；结构检查不等于视觉验收。

## 设计与范围

- 采用系统字体、原生 HTML/CSS/JavaScript；没有第三方脚本、字体、外部图像、遥测或数据请求。
- 主要内容在禁用 JavaScript 时仍可阅读；自动目录和阅读位置提示需要 JavaScript。
- 流程使用可选中的 HTML 文字和有序列表表达，不把关键信息烧进图片。
- 这是阅读型页面，不提供幻灯片切换、业务数据处理、模型调用或专门的打印排版。当前版本只对桌面阅读做验收；若要正式打印或移动端交付，请按实际场景补充样式与验证。
- HTML 不隔离恶意内容。只加入有权使用的文本、链接和素材，不把凭据、真实客户材料或未经授权的来源带入公开副本。
