# 旅行规划与路书交付

把旅行需求变成有依据、能执行、可调整的计划；网页是可选交付，不是默认目标。适合行程比较、审核、局部调整及路书制作。首版重点覆盖国内短途不自驾和多日自驾；不承诺跨境政策、特殊健康需求或全部目的地已验证。

## 怎么用

直接按下表执行即可；让 AI 执行时，明确要求它先读 [travel-planning/SKILL.md](../skills/travel-planning/SKILL.md)。安装时复制完整 `skills/travel-planning/` 目录，依宿主支持的位置安装；文件存在不等于已发现、已触发或正确执行。本包不安装联网能力，不代订票或付款。

| 步骤 | 最小动作与产物 |
| --- | --- |
| 1. 需求与现状 | 复用已知信息；确认当地日期、起点、人数、交通、已订项目、体力、行李和预算口径。分清硬约束、偏好与假设。 |
| 2. 证据 | 先查影响决策的具体日期、开放、班次、票务包含项和寄存。记录来源、查询时间、适用日期及未解决条件。 |
| 3. 路线与住宿 | 必要时比较少量路线骨架，再推荐一个。比较门到门交通、折返、行李存取、疲劳、酒店入口与晚间交通。 |
| 4. 时间与预算 | 从返程硬截止倒排；同一时间轴包含吃饭、取物、等车和休息。费用区分按人、按间、按车；套餐不重计，未知不当零。 |
| 5. 天气与调整 | 天气对应具体活动和时段，写明复核时间、减项与取消条件；天气预报不能替代停航或闭园公告。 |
| 6. 交付与验收 | 默认文字。网页用同一行程数据，一张总览地图配交通卡片；实际测试切换、导航、预算、天气失败和手机布局。 |
| 7. 发布与复盘 | 确认公开范围并脱敏。核对源文件、构建产物、匿名目标页面及交互；真实反馈才用于调整方法，不公开私人画像。 |

## 可直接使用的任务请求

> 请按 travel-planning Skill 审核这份旅行需求与现有订单。先给主方案、依据、成立前提与关键未知，再给可执行日程；不要重复询问已知信息。明确交通与行李衔接、预算单位、天气复核和返程缓冲。只在我要求时制作网页或公开发布，不把估算与候选写成已核实或已预订。

## 检查与限制

详见 [验证记录](../skills/travel-planning/evals/VALIDATION.md)。数据检查器使用 Python 3.10+ 标准库：

```sh
python skills/travel-planning/scripts/check_trip.py skills/travel-planning/assets/synthetic-trip.json
python -m unittest discover -s skills/travel-planning/evals -p 'test_*.py' -v
```

退出码 0 表示所支持字段没有发现一致性问题；1 表示发现问题；2 表示输入或用法错误。它不是路线规划器、事实核验器或完整 JSON Schema。未知费用会报告待处理，不生成貌似完整的总价。真实行程不要直接套用虚构算例的时间和价格。

首版含方法、数据约定、合成算例、校验器和场景验收，不含通用网页生成器。使用一个任务入口，详细规则从 Skill 按需读取；来源和维护边界见 [sources.md](../skills/travel-planning/references/sources.md)。
