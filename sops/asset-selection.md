# 选择值得分享的小件

适用于从已有 Skills、SOP、模板和脚本中选择分享内容。目标是让别人更容易完成真实任务，同时避免维护两套正文、重做已有评估或公开无权分发的材料。

## 先复用已有判断

先找资产的正式主源、现有台账、最近适用的审计或实际使用记录。用已有证据区分是否找到、是否正确使用、是否带来帮助以及维护负担；缺少真实消费者或可比分母时保留未知，不凭文件数量、调用次数、静态校验或生命周期标签推断长期收益。

这与[沉淀与后续复用标准](../skills/session-closeout/references/learning-reuse.md#后续有效性怎么判断)采用同一口径。发布任务消费已有有效性结论，只补本次新增、变化或过期的证据，不另建一套长期评分表。没有新输入，不为发布重跑未变化的实际调用。

## 按任务组织入口，先比较再新增

新增内容前先与现有项目比较**使用者、任务目标、输入和产物**，不要仅因文件形式或目录不同，就当成独立能力。

| 与现有内容的关系 | 如何呈现与维护 |
| --- | --- |
| 同一任务的 Skill、简明 SOP 或示例 | 合并为一个任务入口，在里面说明默认用法、替代路线及何时升级；保留必要的独立取用方式。 |
| 完整能力与其模板、图样或辅助脚本 | 以完整任务为入口，配套内容放在其用法中；不把每个附件再列为同级产品。 |
| 名称或实现相近，但任务与产物不同 | 可以独立列出，但必须一句话说清选用差异；如整份文档转换与 PDF 指定页提取。 |
| 同一流程的上下游 | 按实际消费者分工，必要时互相引用；维护者的选品、发布工具不挤入普通用户任务表。 |
| 同一任务且没有独立增量 | 合并正文或引用现有实现，不为维持资产数量保留重复入口。 |

根 README 的任务表每行只保留一个推荐入口，名称以使用者能看懂的任务或能力表述；入口页再分流。简明版保留独立使用所需的最小步骤，详细规则由同一主源维护，不能把两份完整规范长期平行复制。中英文入口、子指南和实际能力一起更新；不为凑数设固定行数，也不因新增 Skill、SOP、模板就自动增加入口。

## 再检查发布差异

| 问题 | 应有证据或处置 |
| --- | --- |
| 谁会在什么任务用它？ | 明确输入、动作和产物；若只是当前项目事实，留在项目。低频本身不等于无价值 |
| 单独拿走能否使用？ | 必要成员完整，依赖、路径、账号和宿主条件清楚；方法有用但环境不完整时保留候选 |
| 能否合法、适当地分发？ | 确认作者或固定上游、许可、素材与数据范围；公开许可不覆盖第三方或公司材料 |
| 发布后能否维护？ | 唯一编辑源、固定版本、差异、必要验证和恢复入口明确；避免与成熟上游长期平行复制 |

**发布前按首次使用者的路径走一遍：任务表 → 推荐入口 → 选择用法 → 准备依赖 → 找到输入与产物。** 检查链接、锚点、默认建议、重复或互相矛盾的描述。宣称示例能直接用于某个命令时，要实际检查该样例与指定入口；只支持概念参考或需要改写，就前置说明。文件扩展名相同、属于同一图型或链接到同一个 Skill，不证明语法兼容。导航检查、实际调用和长期收益分别记录；没有执行的检查不能写为通过。

生命周期、使用效果和发布就绪度分别判断。`validating` 可以随明确限制公开，`active` 也不表示拥有再分发权。没有独立 LICENSE 不自动证明不可公开，也不能仅凭本地可读或放在用户目录就认定自有。

选择处置：完整且获准的内容发布；有价值但缺来源或依赖的内容保留具体候选；已有成熟上游优先引用固定版本；私人配置和项目事实按既有归属保存。尚未获准公开的材料留在本地，公开分支或 PR 不是私密待审区。

## 发布结果如何回流

只把本次新增事实回到资产原有记录：导出了什么、实际验证范围、远端固定提交、失败或限制。发布成功不改变原有有效性结论，不证明接收侧安装或自然使用，也不重置原验证窗口。

修订默认先回唯一编辑源。用户明确授权的源外维护，须通过已有协作入口回传固定提交、受影响路径与回源责任；主源合并并读回前保留待办。下一次导出先合并远端差异，**不得仅刷新基线或批准摘要，再用旧正文覆盖已授权修订**。远端已发布、主源已合并和本机已采用分别确认；不为这种交接另建重复台账。

后续手动审计读取这些回执，仅复核新增、变化、到期、高风险或反复摩擦对象；发现重复返工或成本上升时，再按已有机制收窄、修订或退出。发布流程、手动审计和实际任务共用证据，各自承担不同处置。

> 请从【明确资产范围】选出适合【目标使用者】复用的内容。先复用现有审计和真实任务证据，保留未知；比较与现有入口的任务和产物，同一任务的不同形式合并导航。只补来源、许可、隐私、必要依赖、独立用法和本次变更验证，检查首次选用路径及所宣称的示例兼容性。按已获准范围发布并回源，未就绪项写明具体缺口、责任和触发条件。不要因为未发布就判低价值，也不要建立第二套长期有效性台账。
